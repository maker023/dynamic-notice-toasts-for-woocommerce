Notice Interception Architecture

How WooCommerce Dynamic Notice Toasts eliminates layout shifts and intercepts every alert vector

1

Server-Side Interception (PHP)

In class-wc-toasts-interceptor.php, hooks into template_redirect and woocommerce_output_all_notices at priority 1.

  • Extracts notices via wc_get_notices()
  • Calls wc_clear_notices() so templates omit static markup
  • Injects suppression CSS in wp_head
  • Serializes notices into frontend JS payload
2

AJAX Event Interception (JS)

In wc-toasts-frontend.js, hooks directly into WooCommerce jQuery triggers and native response pipelines.

  • $(document.body).on('added_to_cart')
  • $(document.body).on('checkout_error')
  • $(document.body).on('applied_coupon')
  • Global ajaxSuccess inspects failure fragments
3

MutationObserver Fallback

Catches rogue notices appended directly to the DOM by 3rd-party plugins, checkout gateways, or custom themes.

  • Observes .woocommerce-notices-wrapper and body
  • Instantly sets display: none !important
  • Parses inner text and action links
  • Converts dynamically into toast with zero delay

The Intelligent Action Link Parser

WooCommerce frequently packs HTML links inside notices, like <a href="/cart/" class="button wc-forward">View cart</a> or <a class="restore-item">Undo?</a>. Rather than leaving messy unstyled anchor tags inside text, the engine:

Before (Default WooCommerce Markup):
<div class="woocommerce-message"><a href="/cart/" class="button">View cart</a> “Shirt” has been added to your cart.</div>
After (Toast Engine Transformation):
Clean Message: “Shirt” has been added to your cart.
Action Button: View cart →
