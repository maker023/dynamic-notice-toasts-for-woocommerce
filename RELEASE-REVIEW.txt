1.2.1 FIXES
- Classic checkout validation errors reach the shopper again. With default banners hidden, 1.2.0
  emptied WooCommerce's notice templates during AJAX requests, so the checkout response arrived with
  no messages and WooCommerce showed its generic "error processing your order" text.
- Invalid coupons show WooCommerce's error as an error toast instead of "applied successfully".
  WooCommerce 11.2 triggers applied_coupon after errored_coupon for failed coupons.
- Each notice produces one toast: event handlers take WooCommerce's freshly inserted markup and the
  observer skips it. The duplicate ajaxSuccess parser was removed.
- Only WooCommerce button links become toast actions; links inside a sentence stay in the message,
  and WooCommerce's own notice markup is never modified.
- Each entry in an error list becomes its own toast.

TESTING SCOPE
- This is not a full matrix of every WordPress/PHP/WooCommerce version, browser or third-party theme.
- SQLite was used for the local integration fixture. CI is configured for WordPress Plugin Check's wp-env environment.
- Classic WooCommerce notice handling was exercised; broad Cart/Checkout Blocks compatibility is not declared.
  Test your actual checkout, payment/shipping extensions, mobile devices and screen readers on staging.
- Custom colors are validated as colors, but contrast depends on the chosen combination.
  Automatic foreground selection prefers the higher-contrast palette color; it does not guarantee WCAG conformance.
